## 发现并已修复的问题

| 编号 | 问题 | 影响 | 修复 |
|---|---|---|---|
| R-01 | 初版 heartbeat 先 tick 再计算静默时长，导致 `updatedAt` 已对齐为当前时间，6 小时静默事件永远不会触发 | cron 的 lonely 规则失效 | 在 tick 前捕获 `silenceAgeMs`，随后用该值执行 `appraiseCron` |
| R-02 | 全局配置 `enabled: false` 时，核心服务仍可处理 L0/L1；`/mood off` 后消息和工具事件仍可能更新状态 | 默认禁用的安全边界不完整 | 在消息、工具、心跳和注入路径均增加全局与状态开关门控；新增回归测试 |
| R-03 | 极限单事件位移的二进制浮点边界会显示为略大于 `0.35` | 测试误报，不是算法越界 | 测试使用 `1e-12` 数值容差，保持实现上限不变 |
| R-04 | 并发测试以 habituation 键数量验证，但 50 次 tick 本应按 30 分钟衰减早期键 | 测试模型与规格冲突 | 改为验证有界事件日志的有序尾部与最终时钟，检验排队写入未被 tick 覆盖 |
| R-05 | 状态目录兜底硬编码为 `/root/.openclaw/workspace/affect` | 非 root 安装会把状态写到自身 workspace 之外 | 依次解析显式配置、`api.workspacePath`、配置里的 workspace、`OPENCLAW_WORKSPACE`，最后回落到当前用户 home |
| R-06 | 时区兜底硬编码为部署者本地时区 | 未配置 `proactive.tz` 的使用者会拿到错位的安静时段与睡眠窗口 | 兜底改为 `UTC`，并在 schema 与 README 中要求显式设置 |

## 部署阻塞项

以下不是核心算法缺陷，而是生产接线必须完成的兼容性核对。它们只影响 `src/index.ts`：

1. 确认入站消息的真实事件名称、文本字段、用户 ID 和消息 ID 字段。
2. 确认代理启动前的提示注入钩子，以及返回字段是否接受 `appendSystemContext`。
3. 确认会话重置、网关退出、心跳注册和命令注册的准确 SDK 签名。
4. 将 `src/openclaw-sdk-shim.d.ts` 替换为与目标 OpenClaw 版本匹配的真实 SDK 依赖后，执行发布编译和 `openclaw plugins inspect --runtime`。

> 在完成上述核对前，不应启用插件。核心系统的审查可以继续，且不依赖这些接线细节。
