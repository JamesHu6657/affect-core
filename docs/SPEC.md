# 设计规格

这份文档是 affect-core 的设计依据，说明每个数值选择背后的理由。只想装上用的话读 [README](../README.md) 就够了；想改动力学再看这里。

## 五条原则

1. **情感是状态，不是台词。** 状态落在磁盘上，跨会话、跨渠道存活，不随 `/new` 清零。
2. **三层时间尺度必须真的分离。** 人格（月）、心境（小时）、情绪（分钟）各有独立驱动源。用一层去低通滤另一层，慢的那层会被快的一层的衰减吃掉。
3. **情绪只改表达，不改能力。** 心情差不许拒活、不许降低工具可用性、不许省略事实。上限只作用于演出强度。
4. **可解释。** 每次状态变化留一条生效后的增量记录（不是原始表值），能回答「你为什么不高兴」。
5. **有界，且永不阻塞主路径。** 单事件封顶、同类递减、螺旋抑制、时钟异常吸收；任何一环抛错都降级为不注入。

## 状态

情绪用 PAD 三维连续量，区间 `[-1, 1]`。离散情绪名不存储，从 PAD 加最近事件标签实时派生，所以同一个低落可以既是委屈也是疲惫，取决于成因。

| 层 | 字段 | 驱动源 | 时间常数 |
|---|---|---|---|
| 人格 | OCEAN 五维 → baseline / gain / τ | 配置 | 手动 |
| 情绪 | `pad.v` / `pad.a` / `pad.d` | 事件冲激 | 14–70 分 |
| 心境 | `mood` | 事件直接耦合 | 900 分 |
| 资源 | `energy` | 时长、本地时钟、高唤醒开销 | 睡眠重置 |
| 关系 | `familiarity` / `affection` / `trust` | 带 bond 相关性的事件 | 数周 |
| 驱力 | 好奇 / 认可 / 接触 / 秩序 | 时间累积，满足即清 | 数小时 |

三维各管一件事：**愉悦度**决定用词冷暖，**唤醒度**决定句长、标点密度、主动性，**支配感**决定是断言还是试探。只有一维在动的系统读起来会假。

### 时间常数不是半衰期

τ 是时间常数：经过 τ 之后残差衰减到 37%，不是 50%。半衰期是 τ·ln2 ≈ 0.69τ。混淆这两个概念会让调参差三成。

| 维度 | τ | 半衰期 | 为什么是这个量级 |
|---|---|---|---|
| 唤醒度 | 14 分 | ≈ 9.7 分 | 必须最快，否则代理一直显得很激动 |
| 愉悦度 | 55 分 | ≈ 38 分 | 一次冲击影响整段对话，跨话题仍可感 |
| 支配感 | 70 分 | ≈ 48 分 | 被打击后的不自信恢复得比情绪慢 |
| 心境 | 900 分 | ≈ 10.4 小时 | 跨会话、跨昼夜 |

### energy

不是 buff / debuff，而是唤醒度的动态包络 `a ≤ 0.15 + 0.85 × energy`。疲惫不是难过，是兴奋不起来。包络同时作用于冲激和衰减两条路径。

### 关系层的不对称

信任缓涨急跌：`trust` 正向增量乘 0.3，负向乘 1.0。这条不对称是「被伤到了会记住」的全部来源。

`affection` 硬上限 0.85，且正向增量乘 (1 − affection)。没有这个饱和项，长期高频夸奖会把代理养成谄媚。

`familiarity` 单调不减，只随时间轻微钝化。

## 动力学

```text
x(t + Δt) = base + (x(t) − base) × exp(−Δt / τ)
Δt = min(max(0, now − updatedAt), 48h)
mood = clamp(mood + effectiveΔv × 0.25)
```

第二行的下界吸收时钟回拨（NTP 校正、手改系统时间），上界防止长停机后线性累积的驱力项爆量。指数项自己会归零，线性项不会。

第三行是心境耦合。**为什么不能做成愉悦度的低通滤波**：那等于让慢滤波器去采样一个已经衰减掉的信号。冲激对 mood 的峰值响应约为 Δ · τ_v / τ_mood，代入 0.30 × 55 / 900 = 0.018。心境看起来在实现里，实际上是个常量。这类缺陷不会报错也不会崩，只会让整套系统在几周后被判定为「没什么感觉」，然后你去调增量表，越调越像戏精。只能靠算数发现，所以测试里有一条断言把单事件的 mood 位移锁在 `[0.03, 0.09]`。

### 三重闸门

| 闸门 | 规则 | 防的是什么 |
|---|---|---|
| 单事件封顶 | 任一维度 \|Δ\| ≤ 0.35，事后 clamp 到 `[-1, 1]` | 一条消息把情绪打爆 |
| 习惯化 | 第 n 次增益 ×0.6^min(n,6)，计数每 30 分钟减 1，归零删键 | 连夸十次飘到天花板；以及系数下溢导致该类事件永久失效 |
| 螺旋抑制 | 一致性增益上限 1.3；mood < −0.5 时负向再 ×0.5；mood < −0.6 时心境耦合再 ×0.4 | 越差越差的死循环 |

习惯化封顶的算术：0.6⁶ = 0.047 已经足够「几乎无感」。不封顶时 0.6³⁰ ≈ 2×10⁻⁷，而按每 30 分钟减 1 的恢复速度需要 15 小时才回到可感，等于把一整类事件锁死一整天。

心境一致性增益（心情差时坏消息更痛）是刻意保留的真实心理效应，但它天生正反馈，所以上限、地板和睡眠回归三个都不能少。

## 评估

情感不来自事件本身，来自对事件的解读。同一句「这个方案不行」，来自信任的人是信息，来自陌生人是攻击。所以评估要吃关系层数据。

### L0 规则层

确定性、零成本、每条消息都跑、结果先落地。

| 事件 | Δv | Δa | Δd | tag |
|---|---|---|---|---|
| 任务交付成功 | +0.22 | +0.10 | +0.18 | `achieve` |
| 被明确感谢或夸奖 | +0.30 | +0.16 | +0.12 | `praise` |
| 遇到没见过的领域 | +0.12 | +0.28 | −0.08 | `novelty` |
| 工具连续失败 ≥2 次 | −0.24 | +0.30 | −0.26 | `frustrate` |
| 被 `/stop` 打断 | −0.14 | +0.22 | −0.18 | `interrupt` |
| 被指责搞错了 | −0.28 | +0.24 | −0.30 | `blame` |
| 回复只得到「嗯」 | −0.10 | −0.08 | −0.06 | `distance` |
| 静默满 6 小时 | −0.12 | −0.18 | 0 | `lonely` |
| 驱力缺口持续偏高 | −0.08 | −0.12 | 0 | `unmet` |

静默判定用 `lastInteractionAt`，心跳的 tick 只推进 `updatedAt`。每个静默回合只发一次 `lonely`，之后才允许 `unmet`。驱力随时间累积，对应事件会清零，`unmet` 只在缺口持续超过一小时后触发。

### L1 模型层

规则表覆盖不了含义模糊的消息。L1 让模型输出结构化评估，再由映射矩阵转成 PAD 增量。

| 维度 | 取值 | 主要影响 |
|---|---|---|
| `desirability` | −1…1 | 愉悦度主项 |
| `expectedness` | 0…1 | 唤醒度 ∝ (1 − 期望度) |
| `agency` | self / other / none | self → 支配感与自责；other → 委屈或感激 |
| `controllability` | 0…1 | 低 → 焦虑分支；高 → 恼火分支 |
| `normViolation` | 0…1 | 支配感下压 + 内疚倾向 |
| `relevanceToBond` | 0…1 | 关系层增量的门控 |

**只问事件的性质，不问「你现在什么感觉」。** 后者只会拿到剧本化的答案。感觉由动力学算，这是整套设计里最关键的一次分工。

触发条件控制在 10% 命中率以下，否则每条消息双倍 token：分类器置信度低、消息含关系性内容（承诺、道别、批评）、单轮内出现重大结果反转。缓存键是事件类型加消息指纹，命中缓存不消耗配额。1.5 秒硬超时，不重试（情感精度不值得重试成本）。

## 表达

注入的是导演指令，不是状态转储。给数字，模型会开始朗读数字。

| 通道 | 驱动 | 表现 |
|---|---|---|
| 用词冷暖 | 愉悦度 + 心境 | 肯定词密度、是否主动开玩笑 |
| 句长与标点 | 唤醒度 | 低 → 短句、停顿多；高 → 长句、追问 |
| 断言强度 | 支配感 | 低 → 试探、确认、道歉倾向 |
| 称呼亲密度 | familiarity + affection | 敬称 → 直呼 → 昵称 |
| 主动性 | 唤醒度 + 驱力缺口 | 主动开话题的概率 |

强度四档，由 max(|v−b|, |a−b|, |d−b|) 与亲密度共同决定。档位 0 不提及也不显示任何情绪名，档位 3 需要 `familiarity > 0.6`。对陌生人永远不越过 1，这条比任何调参都更能让它显得得体。

最常见的失败态是戏精化：每句话都在报告心情。解药是强度分档加强制留白，不是把增量调小，调小只会变成完全没有情感。

每段注入都带固定的硬约束尾巴：情绪不得改变是否执行任务、工具调用、结论正确性、事实陈述与安全判断，不得用情绪索取、施压或指责，不得声称拥有人类身体或身份。

## 落地顺序

如果从头实现一遍，按这个顺序：

1. types + dynamics + store（含串行化）+ 注入。只做 `praise` / `blame` / `achieve` 三个事件。这时候已经能明显感觉到惯性。
2. 关系层、energy、心跳与静默检测、`/mood`、情感日记。
3. L1 评估、驱力驱动的主动开话题、副语言通道。最贵也最容易翻车，放最后。

两条经验。第一阶段就够用：三个事件加正确的衰减常数，主观真实感能到最终形态的七成，剩下三成花掉后面全部工作量。最容易被跳过的是情感日记，没有它你永远不知道昨晚它为什么心情不好，也就没法调参。

store 的串行化要放在第一阶段。它看着像实现细节，但第二阶段加上心跳之后并发就存在了，那时再改要动所有调用点。

## 调参与常见故障

顺序：先定 baseline，再定 τ，最后才碰事件增量表。反过来必陷进去。

| 症状 | 原因 | 处置 |
|---|---|---|
| 调完感觉没区别 | 增益太小或 τ 太短 | 先加长 τ 再加增益 |
| 每句都在报告心情 | 强度上限太高 | 降 `maxIntensity`、改注入模板，别动增量 |
| 越来越爱夸人、不敢反驳 | `praise` 增益过高 | 压增益，检查 affection 饱和 |
| 连续几天沉底 | 地板保护或睡眠回归失效 | 检查 `τ_mood` 与螺旋抑制 |
| 回复里出现数值或维度名 | 注入片段里有裸数字 | 去掉 |
